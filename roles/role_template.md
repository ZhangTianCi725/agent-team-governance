# 角色定义模板（Role Template）

> 每个 Agent = 一份「角色说明书（SKILL）」+ 一份「私有状态（STATE）」+ 一份「共享事实流（LOG）」。
> 治理的关键不是 Agent 有多聪明，而是**它的边界与产出契约是否被写死**。

---

## 1. 角色说明书（SKILL）

| 字段 | 填写 |
|:--|:--|
| `id` | 例如 `researcher` |
| `title` | 例如「研究员」 |
| `mission` | 一句话：这个角色存在的唯一目的 |
| `inputs` | 它可以读什么（哪些数据 / 哪些上游角色的产出） |
| `outputs` | 它必须产出什么（产物路径 + 契约字段） |
| `forbidden` | 它**绝不能**做什么（越界 = 违规，落 review） |
| `escalate_to` | 遇到边界外的问题，移交给谁 |

## 2. 私有状态（STATE）

- 唤醒快照（3 行：当前状态 / 关键认知 / 下一步）
- 待办清单（每条带三态：`[ ]` 待办 · `[@]` 阻塞（必须写阻塞方）· `[✅]` 完成）
- **私有状态不是沟通渠道** —— 别的 Agent 读不到，别把「等 X」写在这里当通知（那等于没通知）。

## 3. 共享事实流（LOG）

- 只追加（append-only），按时间累积。
- 每条消息分两类：
  - **知会**：只陈述事实，不要求对方动作。
  - **行动项**：以 `to-<角色>:` 开头 + 一句话要求 + **验收标准**。
- 写完必须回读自证（确认"我的这条"确实落地了）。

## 4. 产出契约（Contract）

每个产出必须自描述，至少含：

```json
{
  "agent": "researcher",
  "produced_at": "2026-01-01T10:00:00+0800",
  "data_date": "2025-12-31",
  "keys_available": ["code", "date", "value"],
  "output_path": "data/out.jsonl"
}
```

> 有契约，第三层「自我审查」才能自动判它新鲜度、键匹配、可达性。
> 没有契约的产出，等于没有治理的产出。
